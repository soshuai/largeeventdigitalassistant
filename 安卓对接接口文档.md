## 五、接收人证核验数据接口

### 接口说明

用于设备端上传人员证件核验记录数据。

### 请求地址

```
POST /receiveCheckPerson
```

### 请求方式

Content-Type: application/json

### 请求参数

表格







| 参数名             | 参数说明                   | 必填 | 类型    |
| :----------------- | :------------------------- | :--- | :------ |
| entryId            | 验证记录 ID                | 是   | String  |
| verifyStatus       | 验证结果                   | 是   | Integer |
| verifyTime         | 验证时间                   | 是   | String  |
| direction          | 进出方向（0 进入，1 离开） | 是   | Integer |
| equipmentId        | 设备 ID                    | 是   | String  |
| equipmentName      | 设备名称                   | 是   | String  |
| locationId         | 场馆型位置 ID              | 是   | String  |
| locationName       | 场馆型位置名称             | 是   | String  |
| zoneLocationId     | 分区型位置 ID              | 否   | String  |
| zoneLocationName   | 分区型位置名称             | 是   | String  |
| name               | 人员姓名                   | 是   | String  |
| cardNumber         | 证件编号                   | 是   | String  |
| cardId             | 证件 ID                    | 是   | String  |
| createTime         | 创建时间                   | 是   | String  |
| isDetectedStatus   | 核酸检测状态               | 是   | String  |
| closeContactStatus | 密接状态                   | 是   | String  |
| positiveStatus     | 阳性状态                   | 是   | String  |
| activityId         | 活动 ID                    | 是   | String  |
| imageName          | 抓拍图片文件名称           | 否   | String  |
| remark             | 备注                       | 否   | String  |

### verifyStatus 说明

表格







| 值   | 说明                 |
| :--- | :------------------- |
| 1    | 未识读出证件         |
| 2    | 无效证件             |
| 3    | 无权通行（关注人员） |
| 4    | 证件已注销           |
| 5    | 证件未激活           |
| 6    | 无权通行             |
| 8    | 验证通过             |
| 9    | 请检查证件           |

### direction 说明

表格







| 值   | 说明 |

=4都是属于未激活的状态。未激活证件，验证时候提示未激活，属于默认不可通行模式。不启用激活的情况，EventState<=5都是正常的。为增加证件注册号（辅助证件编号）的查询效果，应将不同辅助证件的首位采用不同的字母，用于保障通过注册号能查询到该证件。一、验证规则   1.设备权限每一个验证设备验证之前需要选择配置主活动、子活动、场馆位置和场馆分区【场馆位置和场馆分区是并列的，类型不同，比如场馆位置：鸟巢西南门、鸟巢东北门 场馆分区：封闭线、红区验证等】，然后根据场馆位置和分区位置LocationID、ZoneLocationId获取相关权限列表含【场馆、分项、分区权限、区域权限】等的多条记录。这多条记录共同组成了该设备的验证权限，即该设备所在位置允许通行的权限。2.证件权限每一张证件，含有完整的证件权限信息，跟验证相关的主要字段：passType【证件类型】、effectiveDateOfDayPass【日卡的有效时间】、chipid【芯片号】、eventStatus【证件状态】、venuePrivileges【场馆通行权限】、areaPrivileges【分区通行权限：红、
蓝、】、zonePrivileges【区域通行权限：1,2,3,4,5,6】3.验证逻辑通过芯片触发，【通用验证规则】，人证是否合一：否【提示“人证不合一”】 不开闸，上传“9-请检查证件”之上传记录，否则【提示“请通行”】、开闸，上传“8-通过”的验证记录 。通过人脸触发，未找到证件【提示无证件】，上传“未识读出证件”验证记录；如找到证件，进入【通用验证规则】，验证规则通过，提示“请通行”，开闸，上传“8-通过”的验证记录 。 Passtype：默认三种卡（MP、TP、VP），对应老版系统的三种证件大类 01：实名证件； 02： 现场绑定实名证件（未绑定不允许通行）；03：非实名证件（无需人证合一，比如VIP证件、非实名证件等）。MP：实名注册卡，带人像；TP：当日临通卡（现场绑定的非实名卡）；VP：无需实名的VIP卡，读卡即可通行。其他辅助证件类型可根据活动需要，逐渐增加，比如观摩证、访客证、升级卡等。   【通用验证规则】主要有以下验证步骤：验证是否注销、验证证件类型、验证证件有效期、验证证件权限、验证人证合一。
验证是否注销：验证是否注销，如已注销，提示“证件已注销”，然后按状态上传验证记录，软件跳出验证逻辑，否则继续执行。验证证件有效期：TP验证effectiveDateOfDayPass是否为当日，否提示无效证件；MP、VP，验证开始时间和结束时间，在这个时间段内有效，如果时间字段为空也验证有效。是提示证件已失效，然后按状态上传验证记录，软件跳出验证逻辑，否则继续执行。验证证件权限：多种权限判断，比对证件权限是否大于等于场馆权限，否提示“无权通行”，然后按状态上传验证记录，软件跳出验证逻辑，否则继续执行。验证证件类型：VP类型直接跳到请通行、开闸及上传通行记录；TP验证是否绑定，否提示“证件未绑定”，然后按状态上传验证记录，软件跳出验证逻辑，否则继续执行；MP直接进入下一步骤。验证人证合一：人脸触发模式无须人证合一，手持设备人证合一可选，通道设备人证不合一提示“请检查证件”，其他设备提示“人证不合一”，然后按状态上传验证记录，软件跳出验证逻辑，否则继续执行。以上验证逻辑为新版的验证二、记录存储
